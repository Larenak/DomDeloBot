# ДомДело

«ДомДело» превращает неформальное сообщение в домовом чате MAX в одно коллективное дело: проблема → подтверждения соседей → назначение → работа → фото результата → проверка жильцами.

Это первый рабочий срез MVP. В нём уже доступны сквозной сценарий мини-приложения, API, PostgreSQL-модель, дедупликация, workflow, загрузка фото, outbox и защищённый webhook. Бот проводит жильца через описание и фотографию, показывает найденный дубль и по выбору присоединяет сообщение к существующему делу либо создаёт отдельное.

## Быстрый запуск через Docker

Требуются Docker Engine/Desktop и Compose.

1. Скопируйте `.env.example` в `.env`.
2. Заполните как минимум `POSTGRES_PASSWORD`, `S3_SECRET_ACCESS_KEY` и `SESSION_SECRET` случайными значениями.
3. Выполните:

```bash
docker compose up --build
```

Мини-приложение: `http://localhost:8080`  
OpenAPI UI: `http://localhost:8080/docs`  
Health: `http://localhost:8080/health/ready`

Для остановки: `docker compose down`. Данные сохраняются в именованных volumes. Для полного удаления тестовых данных используется отдельная явная команда `docker compose down -v`.

## Локальный demo-режим без Docker

Нужны Node.js `24.21.0` и pnpm `11.25.0`.

```bash
pnpm install --frozen-lockfile
pnpm build:packages
```

В первом терминале:

```powershell
$env:STORAGE_MODE='memory'
$env:DEMO_MODE='true'
$env:MAX_WEBHOOK_SECRET='local-test-secret'
$env:SESSION_SECRET='local-development-session-secret'
pnpm dev:server
```

Во втором:

```bash
pnpm dev:web
```

Откройте `http://localhost:5173`. В верхней панели можно переключать вымышленные роли жильца, диспетчера и исполнителя.

## Основной сценарий

1. При первом входе житель обязательно добавляет адрес дома. До этого список дел и остальные действия недоступны.
2. Пользователь может добавить несколько домов в «Мои адреса» и выбрать активный дом.
3. Житель нажимает «Создать дело», описывает проблему и прикладывает фотографию в MAX либо делает это в мини-приложении.
4. Объяснимое правило ищет похожие открытые дела только в активном доме — по категории, подъезду, месту, периоду и сходству текста.
5. Житель присоединяется к совпадению либо создаёт новое дело.
6. Диспетчер назначает исполнителя и меняет статусы только по разрешённому графу.
7. Исполнитель добавляет фото результата.
8. Житель подтверждает результат либо оспаривает его.

На текущем этапе адрес можно добавить свободно. Модель данных позволяет позднее заменить это правило кодом приглашения, подтверждением администратора или входом из привязанного домового чата без изменения сущностей дел.

Подробная проверка: [docs/testing-scenario.md](docs/testing-scenario.md).

## Архитектура

Модульный монолит на TypeScript:

- Fastify + официальный `@maxhub/max-bot-api`;
- React + Vite + MAX UI + TanStack Query;
- PostgreSQL 17.11 + Drizzle + `pg_trgm`;
- S3-совместимое хранилище, MinIO только для локального demo-контура;
- outbox worker без Redis;
- Nginx reverse proxy и единый Dockerfile с targets `server`/`web`.

Подробнее: [docs/architecture.md](docs/architecture.md).

## Конфигурация MAX

1. Создайте бота и передайте токен только через `MAX_BOT_TOKEN`.
2. Задайте `MAX_WEBHOOK_SECRET` длиной 5–256 символов (`A-Z`, `a-z`, `0-9`, `_`, `-`).
3. Разместите стенд на публичном HTTPS-домене с доверенным сертификатом и портом 443.
4. Создайте подписку `POST https://platform-api2.max.ru/subscriptions` на `${PUBLIC_BASE_URL}/webhooks/max`.
5. Мини-приложение подключите к тому же боту. Frontend передаёт только `window.WebApp.initData`; `MAX_BOT_TOKEN` во frontend не попадает.

### Запуск локального мини-приложения внутри MAX

MAX не открывает `http://localhost` как Mini App: платформа принимает только HTTPS. Для
локальной разработки проект автоматически оставляет приложение на вашем компьютере и
публикует его через временный HTTPS-туннель на обычном исходящем порту 443.

1. Добавьте `MAX_BOT_TOKEN` тестового бота в локальный `.env`.
2. Выполните:

```powershell
pnpm dev:max
```

Команда собирает общие пакеты, запускает frontend и API, получает временный HTTPS-адрес,
добавляет его в обычную кнопку-ссылку и включает Long Polling. По умолчанию используется
Pinggy, а Cloudflare Quick Tunnel остаётся резервным вариантом. Произвольный URL нельзя
передать в `open_app`: поле `web_app` содержит username бота, чьё приложение уже
зарегистрировано на платформе MAX.
После сообщения «ДомДело готово» отправьте боту `/start` и нажмите «Открыть ДомДело».
В локальном режиме ссылка откроется во внешнем браузере.
Остановка всех локальных процессов — `Ctrl+C`.

Бесплатный туннель предназначен только для разработки: его адрес меняется при запуске,
сессия может быть ограничена по времени, а данные demo-режима хранятся в памяти.
Используйте отдельного тестового бота. Если у бота
есть webhook-подписки, запуск по умолчанию остановится, не удаляя их. Только для осознанного
переключения этого же бота на polling задайте `MAX_POLLING_REMOVE_WEBHOOKS=true`; после теста
production webhook придётся создать заново.

### Постоянный сервер

Для production укажите стабильные адреса:

```dotenv
PUBLIC_BASE_URL=https://domdelo.example.ru
MAX_MINI_APP_URL=https://domdelo.example.ru
MAX_MINI_APP_BOT_USERNAME=domdelo_bot
MAX_DELIVERY_MODE=webhook
```

`PUBLIC_BASE_URL` используется для API и webhook, `MAX_MINI_APP_URL` — для обычных ссылок,
а `MAX_MINI_APP_BOT_USERNAME` включает встроенную кнопку `open_app`. Если frontend и API размещены на разных доменах, домен Mini App всё равно должен
проксировать относительные пути `/api` на backend. При пустом `MAX_MINI_APP_URL` проект
автоматически использует `PUBLIC_BASE_URL`, но только когда тот начинается с `https://`.

Стабильный `MAX_MINI_APP_URL` нужно один раз указать в настройках этого бота на
платформе MAX для партнёров — тогда у чата появится постоянная системная кнопка запуска.
Inline-кнопки `/start` и «Открыть карточку» бот отправляет сам; карточка открывается через
безопасный стартовый параметр `case_<uuid>`.

### Хакатонный стенд на Render

В корне репозитория есть [`render.yaml`](render.yaml): один Web Service отдаёт сайт, API и webhook
с одного постоянного HTTPS-адреса `*.onrender.com`, а PostgreSQL хранит заявки и небольшие
демонстрационные фотографии. В Render откройте **New → Blueprint**, выберите этот репозиторий
и ветку с `render.yaml`. При создании укажите `MAX_BOT_TOKEN` и придумайте отдельный
`MAX_WEBHOOK_SECRET` из 32–64 латинских букв и цифр. Токен нельзя помещать в Git или
передавать браузерному коду.

После состояния **Live** скопируйте адрес Web Service. Его нужно указать в настройках
этого бота на платформе MAX для партнёров как URL мини-приложения. Для сообщений бота
создайте подписку MAX на `https://<адрес>/webhooks/max` с тем же `MAX_WEBHOOK_SECRET`.
Когда Mini App уже привязан, можно дополнительно задать `MAX_MINI_APP_BOT_USERNAME` в
Render: бот начнёт отправлять встроенную кнопку `open_app` вместо обычной ссылки.

Стенд использует один **демонстрационный дом** (`HACKATHON_HOUSE_ID`): каждый пользователь
входит со своей подписанной учётной записью MAX, видит общие дела этого дома и подтверждает
их отдельно от других. Демо-переключатель ролей в Render выключен; для диспетчера нужна
отдельная выдача роли в базе. Не загружайте на общий стенд настоящие персональные данные.

Бесплатный Render засыпает после 15 минут без запросов, а бесплатная база PostgreSQL
действует 30 дней и не имеет резервных копий. Перед показом разбудите стенд открытием
его URL; для надёжного постоянного сервиса потребуется другой тариф или хостинг.

Корневой сертификат Минцифры для подключения к MAX хранится локально в
`infra/certs/russian_trusted_root_ca.cer`; источник — официальный ресурс Госуслуг
`https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer`.

Актуальность MAX API проверена 24.09.2026: используется `platform-api2.max.ru`, `open_app.web_app` содержит username или ссылку на бота с зарегистрированным Mini App, webhook использует заголовок `X-Max-Bot-Api-Secret`.

## Безопасность и данные

- Рабочие секреты не хранятся в репозитории; `.env` игнорируется.
- `initData` проверяется сервером через HMAC-SHA256 и срок выдачи.
- Роль и дом берутся из серверной сессии.
- Создание дела защищено `Idempotency-Key`, webhook — таблицей обработанных событий, смена статуса — `expectedVersion`.
- Фото ограничены JPEG/PNG/WebP и 8 МБ; S3-ссылки имеют ограниченный срок.
- Контейнер приложения запускается от пользователя `node`, web — на unprivileged Nginx.
- В seed нет реальных персональных данных; все сущности помечены `is_demo=true`.

## Известные ограничения

- Для реальной проверки production MAX нужны токен организаторов, стабильный HTTPS-стенд и привязка Mini App в настройках бота; Quick Tunnel подтверждает только локальный тестовый контур.
- На машине разработки Docker отсутствует, поэтому clean-clone Compose-запуск ещё необходимо проверить в среде с Docker.
- Незавершённый пошаговый диалог бота хранится в памяти одного процесса и сбрасывается при перезапуске; зарегистрированные дела и фотографии хранятся в PostgreSQL/S3. До горизонтального масштабирования черновики нужно перенести в PostgreSQL.
- MinIO community upstream архивирован; в локальном контуре сохранён требуемый стек, но перед production-пилотом нужен поддерживаемый S3-вариант.
- Реальные интеграции с УК, ГИС ЖКХ и муниципальными системами не входят в MVP и не имитируются.
