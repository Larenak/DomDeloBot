# Регистрация и права доступа

Вход выполняется через мини-приложение MAX. Сервер проверяет подпись `initData` и создаёт учётную запись с базовой ролью жильца. В рабочем доме выбор адреса **не открывает** дела и не даёт служебные права: доступ появляется после погашения личного приглашения.

## Как проходит регистрация

1. Жилец, диспетчер или исполнитель открывает мини-приложение через MAX. На форме «Личное приглашение» виден его MAX ID.
2. Уполномоченный оператор проверяет проживание жильца либо полномочия сотрудника УК/исполнителя **вне приложения**, определяет рабочий дом и роль.
3. Оператор выдаёт код для конкретного MAX ID, дома и роли. Код действует 72 часа, используется один раз, хранится в базе только как SHA-256 хеш. Передайте его человеку лично, не размещайте в общей ссылке или QR.
4. Человек вводит код в мини-приложении. Сервер повторно получает MAX ID из базы, атомарно погашает код и создаёт назначение роли для этого дома. Если MAX ID, срок или код не совпали, роль не выдаётся.
5. При следующем запросе сервер заново читает роль из `house_role_grants`. Отзыв назначения действует и для ранее выданных сессий.

Адрес из подсказок подтверждает существование дома, а не проживание. MAX ID подтверждает учётную запись MAX, а не трудовые отношения. Поэтому флаг `--verified` в команде означает, что оператор уже проверил основание для выдачи приглашения по доверенному источнику.

## Выдача приглашения оператором

Сначала человек должен один раз открыть мини-приложение через MAX. Оператор узнаёт его MAX ID с экрана регистрации, а UUID рабочего дома — из таблицы `houses` (`SELECT id, address FROM houses WHERE is_demo = false`). Для выдачи нужен доступ к окружению приложения и базе данных; публичного API выдачи кодов нет.

Если проект работает через Docker Compose, выполните из корня проекта:

```powershell
docker compose exec app node apps/server/dist/db/issue-house-invite.js --house-id <UUID_ДОМА> --max-user-id <MAX_ID> --role resident --verified
```

При запуске сервера без Docker, когда `DATABASE_URL` указывает на доступную рабочую базу:

```powershell
pnpm --filter @domdelo/server invite:house --house-id <UUID_ДОМА> --max-user-id <MAX_ID> --role resident --verified
```

Для диспетчера используйте `--role dispatcher`, для исполнителя — `--role executor`. Команда выдаёт новый код один раз в консоль и аннулирует неиспользованные коды той же роли для этого человека и дома. Приглашения для демонстрационного дома не выпускаются.

Если человек не получил код или код истёк, оператор повторно проверяет запрос и выпускает новый. Для отзыва доступа оператор устанавливает `revoked_at` в `house_role_grants`; сервер не доверяет роли, записанной в старой сессии.
